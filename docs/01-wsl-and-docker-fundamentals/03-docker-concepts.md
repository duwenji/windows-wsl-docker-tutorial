## イメージとコンテナ

- **イメージ**: アプリケーションとその実行環境（OSライブラリ、ミドルウェア、設定など）をレイヤ構造で固めた読み取り専用のtarアーカイブ相当のもの
- **コンテナ**: イメージを元に起動された、書き込み可能なレイヤが1枚追加された実行中のプロセス

イメージは何度でも同じ内容で複製・配布できます。コンテナはそのイメージから起動された「実体」であり、1つのイメージから複数のコンテナを同時に起動できます。

## レジストリとタグ

イメージは「レジストリ」と呼ばれる保管場所からダウンロード（`pull`）します。最も一般的なレジストリが Docker Hub です。

イメージは `名前:タグ` の形式で指定します。

```
nginx:latest
postgres:16
node:20-bookworm
```

⚠️ タグを省略すると自動的に `latest` タグが使われますが、`latest` は「常に最新版」を意味するタグ名に過ぎず、バージョン固定の保証はありません。実務では明示的なバージョンタグを指定することが推奨されます。

## Dockerデーモンとクライアント

Dockerは「クライアント・サーバー」構成になっています。

- **`dockerd`（Dockerデーモン）**: イメージの管理、コンテナの起動・停止など、実際の処理を行うバックグラウンドプロセス
- **`docker`（CLIクライアント）**: ユーザーが打つコマンド。`docker.sock`というUnixソケット経由で`dockerd`と通信する

02章でインストールするのはこの`dockerd`本体（Docker Engine）です。`docker run`のようなコマンドを打つと、CLIが`docker.sock`経由で`dockerd`に指示を送り、`dockerd`が実際にコンテナを起動します。

## 03章以降で使うコマンドの全体像

これ以降の章で扱う主要コマンドの全体像だけ、ここで一覧にしておきます。詳細な使い方は03章で扱います。

| コマンド           | 役割                                     |
| ------------------ | ---------------------------------------- |
| `docker run`     | イメージからコンテナを起動する           |
| `docker build`   | Dockerfileからイメージを作る             |
| `docker ps`      | 起動中のコンテナ一覧を見る               |
| `docker volume`  | データ永続化用のボリュームを管理する     |
| `docker network` | コンテナ間通信用のネットワークを管理する |
