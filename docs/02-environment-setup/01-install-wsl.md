# 01 WSLのインストール

## 所要時間

約20分

## 学習目標

- `wsl --install` でWSL2環境を構築できる
- WSL2がデフォルトになっていることを確認できる
- WSL（Ubuntu）のターミナルを開き、Windows側との違いを見分けられる
- `.wslconfig`の存在意義を理解する

---

## 前提条件

- Windows 11（Windows 10の場合はビルドバージョンによって手順が異なるため、Microsoft公式ドキュメントを参照してください）
- BIOS/UEFIで仮想化支援機能（Intel VT-x / AMD-V）が有効になっていること

## WSLのインストール

PowerShellを**管理者権限**で開き、以下を実行します。

```powershell
wsl --install
```

このコマンド一発で、WSLの有効化・Linuxカーネルの最新化・既定ディストロ（Ubuntu）のインストールまで自動的に行われます。完了後、PCの再起動を求められる場合があります。

## ディストリビューションを指定する場合

既定以外のディストロを使いたい場合は、まず利用可能な一覧を確認します。

```powershell
wsl -l -o
```

```
インストールできる有効なディストリビューションの一覧です。
'wsl.exe --install <Distro>' を使用してインストールします。

NAME                                   FRIENDLY NAME
Ubuntu                                 Ubuntu
Ubuntu-22.04                           Ubuntu 22.04 LTS
Debian                                 Debian GNU/Linux
```

バージョンを指定してインストールする例:

```powershell
wsl --install -d Ubuntu-22.04
```

本教材では以降、既定の `Ubuntu` を前提に手順を記載します。

## WSL2がデフォルトであることの確認

```powershell
wsl -l -v
```

```
  NAME      STATE           VERSION
* Ubuntu    Running         2
```

`VERSION`列が`2`になっていない場合は、以下のコマンドで明示的にバージョンを切り替えます。

```powershell
wsl --set-version Ubuntu 2
```

## WSL（Ubuntu）のターミナルを開く

ここまでのコマンドはすべて**Windows側のPowerShell**で実行してきました。しかしこの後の02章では、`apt-get`やDockerのコマンドを**WSL（Ubuntu）の中**で実行していきます。本教材で「WSL側で実行」「WSLのUbuntuターミナルで」と書かれていたら、それはここで説明する画面を指しています。

### 開き方

方法は主に2つあります。どちらでも同じ場所にたどり着きます。

**方法1: スタートメニューから開く**

Windowsのスタートメニューで「Ubuntu」と検索し、表示されたアプリをクリックします。専用のウィンドウが開き、そのままUbuntuのシェルに入ります（初回起動時はユーザー名とパスワードの設定を求められます）。

**方法2: 今開いているPowerShellで`wsl`と入力する**

```powershell
wsl
```

これだけで、同じウィンドウの中身がそのままUbuntu側に切り替わります。

### 「今どちらにいるか」をプロンプトの見た目で見分ける

本教材はこの後も「Windows側（PowerShell）で実行」と「WSL（Ubuntu）側で実行」を何度も使い分けます。今どちらの画面を見ているかは、プロンプト（コマンドを入力する行の先頭）の見た目で区別できます。

| 環境 | プロンプトの例 | 末尾の記号 |
|---|---|---|
| Windows側（PowerShell） | `PS C:\Users\alice>` | `>` |
| WSL（Ubuntu）側 | `alice@DESKTOP-ABC123:~$` | `$` |

迷ったら「`$`で終わっていればLinux（Ubuntu）側、`>`で終わっていればWindows側」と覚えておけば十分です。

### 抜け方

WSL側で`exit`と入力するか、ウィンドウを閉じれば、Windows側の操作に戻れます。

💡 `exit`しても、01章で学んだWSL2 VM（`Vmmem`）自体はすぐには終了せず、裏側でしばらく動き続けることがあります。VMを完全に終了させたい場合は、07章で扱う`wsl --shutdown`が必要です。

## リソース制限の初期設定

WSL2はデフォルトでは搭載メモリの大部分を確保できてしまうことがあります。最低限の初期設定として、ユーザーフォルダに `.wslconfig` を作成しておきます。

ファイルの場所: `%UserProfile%\.wslconfig`（例: `C:\Users\<ユーザー名>\.wslconfig`）

### なぜユーザーフォルダに置くのか

`.wslconfig`が制御しているのは、01章で学んだ「複数のディストロが共有する1つのWSL2 VM」そのものです。このVMは**Windowsのユーザーセッションごとに**起動されるため、設定もWindowsユーザーに紐づく場所（`%UserProfile%`）に置く仕組みになっています。同じPCに複数のWindowsアカウントがあっても、それぞれ独立したWSL2 VM・独立したリソース設定を持てるということです。

（この後インストールするDocker Engineの設定で登場する `/etc/wsl.conf` は、これとは階層が異なり、各ディストロの内部に置く「そのディストロ固有」の設定ファイルです。混同しないよう注意してください。）

また、`%UserProfile%`はそのユーザーが常に書き込み権限を持つ場所なので、`.wslconfig`の作成・編集に**管理者権限は不要**です。仮にシステム全体の共有領域（`C:\ProgramData\`など）に置く仕様だったら、変更のたびに管理者権限が必要になっていたはずです。

```ini
[wsl2]
memory=4GB
processors=2
```

### `wsl --shutdown`は設定を反映するコマンドではない

ここで注意したいのは、`wsl --shutdown`自体は**終了処理のみ**を行うコマンドだという点です。ファイルを読みに行ったり、設定を反映したりする処理は一切含まれていません。

`.wslconfig`が読み込まれるのは、「WSL2 VMが新しく作られる瞬間」だけです。そしてVMが一度起動すると、生きている間はファイルをいくら書き換えても何も起きません。つまり流れはこうです。

1. `.wslconfig`を編集する（この時点ではVMは古い設定のまま動き続けている）
2. `wsl --shutdown`でVMを完全に終了させる（`Vmmem`プロセスがタスクマネージャーから消える）
3. 次に`wsl`関連のコマンドを何か実行すると、VMが存在しないためゼロから新しく作られる
4. その「新しくVMを作る」処理の中で、初めて`.wslconfig`が読み込まれる

つまり、**`--shutdown`が設定を反映しているのではなく、「壊すことで、次の起動時に新しい設定込みで作り直させている」**というのが正確な理解です。この「終了→次回起動時に作り直し」というパターンは、この後の章でネットワークモードの切り替えやメモリ制限の変更でも繰り返し登場します。

⚠️ よくある誤解として、「ターミナルを閉じれば設定が反映される」というものがありますが、これは誤りです。ターミナルを閉じてもバックグラウンドのVM自体は生き続けていることが多く、その場合は設定が反映されません。タスクマネージャーで`Vmmem`が消えたことを確認するか、確実に`wsl --shutdown`を実行してください。

⚠️ また、この設定内容自体はあくまで初期値です。メモリ肥大化（`Vmmem`問題）への詳しい対処は [07-operations-and-troubleshooting](../07-operations-and-troubleshooting/README.md) で扱います。

## 演習

1. `wsl --install` でWSLをインストールする（インストール済みの場合は `wsl --status` で状態を確認する）
2. `wsl -l -v` を実行し、`VERSION`列が`2`であることを確認する
3. スタートメニューから「Ubuntu」を開き、プロンプトが`$`で終わっていることを確認してから`exit`でWindows側に戻る
4. `.wslconfig` を作成し、`wsl --shutdown` 実行後に再度 `wsl -l -v` が問題なく動くことを確認する

## 章末チェックリスト

- [ ] `wsl -l -v` でWSL2ディストロが起動していることを確認した
- [ ] WSL（Ubuntu）のターミナルを開き、プロンプトの見た目でWindows側と見分けられる
- [ ] `.wslconfig` の役割と設置場所を説明できる
- [ ] `.wslconfig`がユーザーフォルダに置かれる理由を、`wsl.conf`との違いを含めて説明できる
- [ ] `wsl --shutdown`が「設定の反映」ではなく「VMの終了」であり、次回起動時に作り直されることで新しい設定が読み込まれることを説明できる
